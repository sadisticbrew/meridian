# meridian — phase 3: graphs, HTML export, TUI

**Hand to the implementing LLM with:** spec 00–03 and this file. Phases 0–2 merged
and green first.

## Scope

The payoff layer. No new data, no new aggregation — this phase renders what already
exists. Order matters: terminal graphs first (cheapest), then HTML export, then the
TUI. Each item is independently useful; if time-boxed, stop after any of them.

## Tasks

### 1. `meridian graph [minutes|dsa|german] [--days N]` (default 30)

Terminal output only, via `guptarohit/asciigraph`:

- `minutes`: per-day stacked totals of project + course + self-study + German
  minutes (one sparkline of daily totals, plus a compact per-subject bar block
  using `█` characters scaled to the window max).
- `dsa`: cumulative solves line + per-pattern solved counts as horizontal bars,
  first-try rate summary line.
- `german`: lesson-number step line.

Everything renders from existing store queries. `--json` not required here.

### 2. `meridian export html [--out FILE] [--days N]`

A **single self-contained HTML file** at `~/.local/share/meridian/export.html`
(prints the path when done). Constraints — all hard:

- No JavaScript. No external URLs (fonts, CSS, images — nothing fetched). Dark
  theme to match the terminal. Charts are **inline SVG generated by Go templates**
  from the data. The file must open offline in a browser from a Hyprland keybind.
- File size < 300 KB. No embedded chart libraries — hand-rolled SVG only.
- Charts, in order: (1) daily minutes, last 30 days, one line per kind with a
  legend; (2) this-week vs last-week minutes per subject (paired horizontal bars);
  (3) DSA solves per pattern (horizontal bars, first-try rate annotated);
  (4) German lesson progression (step line); (5) milestone table.
- Wins-first ordering applies to the page: completed things above gaps.
- No streaks, no gratuitous animation.

Template lives in `internal/views/html.go` via `html/template` with the data
assembled in Go. A golden test pins the structure (IDs of chart sections present,
no `http://`/`https://` resource references in the output).

### 3. `meridian tui` (bubbletea + lipgloss)

Full-screen alt-screen dashboard reusing the phase 1/2 view functions (they write
to `io.Writer`; the TUI captures into a viewport):

- Tabs: `Today` / `Week` / `Subject` / `DSA` (pattern table across all patterns,
  14-day window). Keys: `1–4` or `h/l` switch, `r` refresh, `q` quit. `30s`
  auto-refresh.
- A `s` key starts/stops a session prompt? **No** — the TUI is read-only this
  phase. Logging stays in the CLI (keeps TUI state trivial and avoids the exact
  terminal-wrecking error path the owner documented in his other project).
- Colors: gaps section in muted red, banked section default; lipgloss for chrome,
  but views themselves stay plain text (single rendering source for CLI/TUI/golden
  tests).

## Acceptance criteria

- [ ] `graph minutes/dsa/german` render with a fixture DB; a wide value and an
      all-zero window both render without panicking (edge: division by zero when
      scaling bars — clamp).
- [ ] `export html` output: `grep -c 'src="http' out.html` = 0, size < 300 KB,
      opens in a browser with charts visible (manual check, note it in the PR).
- [ ] Golden test on HTML structure passes.
- [ ] TUI: boots into alt-screen, tabs switch, `q` quits cleanly restoring the
      terminal, `go test` still green (TUI model unit-tested headless: tab state,
      refresh message handling).
- [ ] `make build && make test && make vet` clean.

## Verification

```
make build && make test && make vet
./bin/meridian graph minutes --db /tmp/m.db
./bin/meridian export html --db /tmp/m.db && ls -la ~/.local/share/meridian/export.html
./bin/meridian tui --db /tmp/m.db   # manual: q exits, terminal intact
```

## Out of scope

Any new aggregation logic (if a chart needs a number the store can't produce, add
the *query* to the store, not a compute path in the template), quantify (phase 4),
TUI write operations, config for themes.
